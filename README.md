# 菜篮子 · Little Basket

一个以手机为主的私人买菜 App，运行在单个 HTML 文件里。入口是 [`little-basket.html`](little-basket.html)，本机模式无需构建、远程字体、CDN 或第三方运行时依赖。家庭模式通过 Supabase Free 同步；手机访问静态托管的网站。

## 打开

手机在线入口：**https://niklausyu99.github.io/Little-Basket/**。通过 GitHub Actions 发布；家庭数据需通过自己的专属链接连接。

用支持 JavaScript 的浏览器打开 HTML。也可以在仓库目录运行一个静态服务器：

```bash
python3 -m http.server 4173 --bind 0.0.0.0
```

然后在浏览器打开该服务器上的 `/little-basket.html`。手机需能访问运行服务器的地址；仓库已提供 GitHub Pages 工作流，但只有部署成功后的网站地址才可在手机访问。部分手机文件预览器不执行 HTML 脚本，请使用浏览器或静态站点，而非系统文件预览。

## 添加到手机桌面

正式站点包含 Web App manifest、独立窗口设置、桌面图标和 service worker，可安装为 PWA，无需 App Store。App 右上角齿轮「设置与数据」→「添加到手机桌面」提供操作说明。

- iPhone／iPad：用 Safari 打开正式网址 → 分享 → 添加到主屏幕；若显示「作为网页 App 打开」，保持开启。以后从桌面图标在独立窗口打开。
- Android：用 Chrome 打开，使用安装按钮或浏览器菜单中的「安装应用／添加到主屏幕」。
- 安装与家庭连接是两回事。已连接设备在顶部「家庭厨房 → 复制家庭链接」取得专属链接；「分享给家人」可调用系统分享，复制结果显示在面板内；第一台设备在「家庭同步」粘贴 SQL 初始化时自己保存的连接码。不要将连接码发到聊天或 GitHub。安装后的独立 App 若没有继承浏览器连接，再连接一次即可。

首次联网加载完成后可离线重新打开；已有数据在本机暂存，联网后补传。缓存只包含公开页面和安装图标，不缓存 Supabase 请求、家庭链接或家庭记录。系统清理缓存后仍需联网加载；同步只在 App 打开或回到前台时工作。原始 HTML 保持自包含，PWA 安装使用构建后的 HTTPS 站点。

## 四个页面

- **选购**：按蔬果（含鸡蛋）、肉类、干货、调味、冲饮零食、日用挑东西。默认双列卡片，可用排序右侧的一列／四格／九格图标切换单列列表、双列或三列；选择在当前设备记住，刷新保留，不影响家庭数据。支持默认分类、名称、最近购买和常备优先排序；排序控件位于分类栏下方，采用小号无边框文字按钮，点击后向右展开选项浮层，选好自动收回，也可点外部或按 Escape 取消。支持搜索与手动添加新物品，新物品会留在选购目录供以后使用。长按卡片或点名称旁的「···」可编辑名称／分类或确认删除。文字编辑沿用原 ID、插画和所有关联记录；重名会提示，未保存退出需确认。删除只移除选购卡片和本趟清单关联，保留菜谱、库存与购买历史，可从设置的「已删除的选购物品」恢复；重新添加同名物品也沿用原身份。右下方悬浮插画篮显示待买数量角标、不再带「清单」文字，随这趟物品总数逐步装满；确认添加成功后，食材图飞入篮中并轻弹；手机向下浏览时收窄为 56 px 插画篮子，向上滚动、回到顶部或滑到底部时恢复，缩小时仍可一键预览。支持预览、移除和撤销误选；菜谱食材移出仅影响这一趟，重新加入食材或重新选择菜谱可恢复。每样食材都可添加本次采购备注，预览与完整清单共享同一份内容。购买打钩和缺料详情留在完整清单。
- **清单**：按超市区域分组，勾选已买并划线；支持隐藏已买、分享文字清单、重置本次选购。勾选才写入购买记录；取消勾选可撤回关联的当次记录。支持单项备注和「这一趟的备注」，输入自动保存、随家庭同步，重置清单时一并清空。
- **菜谱**：内置 9 道家常菜、5 锅汤（其中辣子鸡、辣椒炒肉、日式拉面叉烧默认在学）；一键加入菜单、合并食材，按人数换算参考份量。支持「默认／最新添加」排序，按加入顺序将新菜放前面；编辑旧菜不会改变加入顺序。排序仅在当前设备记住，搜索及分类筛选继续生效。长按卡片或点右上「···」可编辑或确认删除整道菜；删除同时清理当前菜单和版本选择，不删共享食材、库存或购买记录。内置菜谱的删除状态会保留，刷新、升级和家庭同步不会自动补回。排骨与煲汤骨分开选购、库存和购买记录（旧合并记录保留为排骨；煲汤骨单独开始，不复制库存）；五花肉可切换酸梅酱版与八角版；没有山药汤。做法注明用户配方与补充参考的区别。
- **小厨房**：常备余量滑块（调料、油、米、燕麦、Milo、蛋白粉等）、生鲜库存，以及最近 30 天的购买记录。常备品和生鲜都能单独添加；录入库存不会伪造购买记录或加入清单。常备余量和生鲜库存各有独立名称／别名搜索、结果数与清空入口，筛选不会改库存；刷新保留搜索和当前小厨房页签；离开后再进小厨房默认常备余量，页签记忆仅在本机当前窗口保存。

## 清单、库存、历史各自保存

| 操作 | 本次清单 | 库存与余量 | 购买记录 |
|---|---|---|---|
| 开始新的一趟 | 清空选菜、补货和勾选 | 保留 | 保留 |
| 每日自动重置（默认关闭） | 跨日后打开、返回或切页时清空 | 保留 | 保留 |
| 勾选已买 | 划线完成 | 记为还有；慢消耗品新的一份设为 100% | 新增一笔 |
| 滑动余量 | 影响是否略过调料 | 仅按手动调整保存 | 不伪造采购记录 |
| 选菜 | 合并同名食材和参考用量 | 不自动扣减 | 不新增 |

生抽、蚝油、料酒、油等慢消耗品的余量不会随着清单重置。正库存调料在选菜时略过；主动补货时仍可确认再买。生鲜在七天内买过，或仍标为家里有，再次加入时会提醒：勾选确实要买的，其余本次略过。已经在当前清单的东西不重复加行。

滑块是剩余量的手动估计，不是按克数计算的自动消耗模型。买新的一份会重置为 100%，不是多瓶库存台账。未记录的库存会显示「未记录／待确认」，不会假设实际拥有数量。

日期按 `Asia/Kuala_Lumpur` 计算。每日自动重置在右上角「设置与数据」里开启，后台不会运行定时清理。过去 30 天是展示范围，完整历史仍保存在数据中。记录支持新旧排序、单笔删除和撤销；删除会撤回该次购入带来的库存，即使已重置清单；删掉最后一笔购入记录后，不再显示这次购买的「家里还有」。后续手动改过的库存保留。生鲜使用「用完了／还有／很多」三档滑条，只停在三个位置，也可直接点文字；当前档位使用柔和砖红／叶绿／深绿并加粗。旧的「还有」保持中档，未知库存保留「待确认」。三档随家庭同步、备份与重置保留，不记录虚构的采购。常备滑块在 0–100% 连续变色，卡片仅保留一个大号余量；未知余量保持中性。

## 数据与后续加菜

本机模式保存在当前浏览器的 `localStorage`（键 `little-basket:v1`）。家庭模式使用专属链接，自动连接并共享清单、库存、余量、菜谱和完整购买历史；不需要家人注册、邮箱或密码。不同家庭的缓存隔离。

首次部署、数据库初始化、家庭链接与 Free 配额见 [Supabase 设置说明](supabase/README.md)。公开 Project URL 与 Publishable key 在 `site-config.json`，不含家庭访问凭证。**这些配置就位不等于家庭同步已完成验收；正式站点已部署；有效家庭链接的真实双设备读写仍由家庭设备验收。**

应用打开后断网可先保存，恢复网络会补传。家人同时修改时先确认保留哪份，不静默覆盖；JSON 备份继续用于恢复误操作和迁移，不包含家庭连接码。导入会先验证并确认替换，已连接时也会同步给家人。换设备前确认「已同步」，或先导出备份。

后续新菜优先通过对话整理，维护 HTML 中的 `SEED_RECIPES` 和 `SEED_INGREDIENTS`。内置数据以稳定 ID 合并，更新文件会补入新菜，不会清空已有购买记录和库存。用户在 App 内修改过的做法会保留。App 里也能添加和编辑菜谱，「在学的」页有相同入口；新菜默认标为在学。新增选购物品自动使用纸袋插画，新增菜谱自动使用餐罩插画；不提供图标选择、上传或替换入口。插画在 HTML 内共用 SVG 定义，不写进家庭数据；专属素材按稳定 ID 优先匹配，开发者补图不需要改名称、ID、配方或历史。来源链接支持多条：填好一行后自动出现空白行，空行不保存；已有的单条来源会兼容显示。

读不到旧存储时，不覆盖原记录；浏览器拒绝保存或存储空间不足时，会显示未保存提示并允许导出备份。

## 验证

当前环境已具备 Python Playwright 与 Chromium：

```bash
python3 tests/test_app.py
python3 tests/test_cloud_sync.py
python3 tests/test_build_site.py
python3 tests/test_pwa.py
python3 scripts/build_site.py --require-cloud
python3 scripts/verify_design_capabilities.py
node .agents/skills/design-taste-frontend/scripts/lint.mjs --app little-basket.html
```

浏览器测试覆盖 320–1440 px、库存与清单独立重置、历史、提醒、滑块、菜谱合并、配方切换、备份恢复、旧数据迁移、保存保护及无外部资源依赖。测试输出写在忽略的 `.test-results/` 中。应用本身不依赖这些测试工具。同步测试使用 RPC 替身；发布后另行比较线上 HTTPS 文件与生产构建。PWA 测试通过真实 service worker 验证新子路径、manifest 与断网重新载入；真实无效链接 RPC 拒绝已验证。有效家庭链接的真实双设备同步、实际 iPhone／Safari 尚未验收。此环境 Chromium 直连线上站点因代理 CA 信任报错，未绕过 TLS 校验；手机尺寸交互在本机服务完成验证。

本轮内容完整性核对见 [历史需求核对](design/reviews/2026-10-20-requirements-audit.md)，新菜做法的实际参考与整理边界见 [菜谱资料](design/recipe-research.md)。新增目录会沿用旧的同名／别名物品身份，补入新菜谱时同步映射食材引用，保留库存、历史及已编辑做法。

## 本轮交互调整（2026-10-20）

- 设置统一到右上角齿轮，移除小厨房重复的回转箭头入口。家庭状态仍在顶栏，设置也能进入家庭专属链接与同步面板；下载图标只用于实际导出。
- 清单顶部常驻小篮子与采购进度：0 样为空，1–3 / 4–6 / 7–9 / 10–12 / 13–15 / 16–18 / 19+ 样逐档变满，最后是鼓鼓的胖篮子。按不同物品总数计算，不按份量，也不因勾选已买而倒空；数量角标仍显示待买数。
- 清单大篮子可点按弹一下；增减物品有短暂弹跳或回落，跨多档逐步交叉淡化，可中途反向。悬浮篮复用同一套 WebP，不额外下载图包；添加成功后食材飞入。尊重系统减少动态效果；动画不写进家庭数据，不持续循环。
- 选购已加入的按钮再次点击，会确认移出，保持在选购页。菜谱再次点击已选按钮会确认取消该菜，保留其他菜或单独补货仍需的食材。移出清单不删除购买历史、库存或菜谱配方。

用户已授权本轮更新 GitHub 并发布；最终线上一致性验收以发布完成后的任务回复为准。

选购另补「快熟面」（Maggi／Maggie、方便面／泡面可搜索），采用用户参考的 Maggi 咖喱组合包装2D插画；梳打饼改用 Hup Seng 黄白条纹及深绿面板包装插画，名称与物品 ID 保持不变，已有库存和购买记录保留。Milo 绿罐与 F&N 炼奶同样按用户实物参考重绘，保留 Logo 和主要文字。

蛋白粉插画使用用户提供的 MMX WHEY ABSOLUTE 桶装参考；重绘直接替换旧图标，名称、ID及已记余量不变。


### 家庭上手与管理（2026-10-20）

「设置与数据 → 快速上手」提供可展开的选购、清单、菜谱、小厨房、家庭共享／安装说明，不自动弹出，不写家庭状态。指南只介绍现有功能。

删除状态采用兼容 version 1 的可选字段：`deletedRecipes` 是已删除菜谱 ID，阻止种子菜谱重建；`hiddenIngredients` 是隐藏的选购身份，实体仍保留供菜谱、库存和历史引用；`ingredients[].textEdited` 保留用户编辑过的名称及分类，不被旧名称迁移覆盖。旧备份缺少这些字段时补空值，新备份、家庭同步和首次本机迁移会保留它们。恢复选购卡片不自动恢复本趟采购；再次加入时正常检查库存。

审查结果、正负向模拟反馈、并发冲突边界及验证依据见 [家庭 UX 与同步审查](design/reviews/2026-10-20-family-ux-audit.md)。所有家庭交互测试均使用隔离浏览器存储与模拟 RPC，没有修改真实家庭生产数据。
