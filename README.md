# 菜篮子 · Little Basket

一个以手机为主的私人买菜 App，运行在单个 HTML 文件里。入口是 [`little-basket.html`](little-basket.html)，本机模式无需构建、远程字体、CDN 或第三方运行时依赖。家庭模式通过 Supabase Free 同步；手机访问静态托管的网站。

## 打开

手机在线入口：**https://niklausyu99.github.io/Cooking/**。2026-10-19 已部署并核对线上文件与生产构建一致；家庭数据需通过自己的专属链接连接。

用支持 JavaScript 的浏览器打开 HTML。也可以在仓库目录运行一个静态服务器：

```bash
python3 -m http.server 4173 --bind 0.0.0.0
```

然后在浏览器打开该服务器上的 `/little-basket.html`。手机需能访问运行服务器的地址；仓库已提供 GitHub Pages 工作流，但只有部署成功后的网站地址才可在手机访问。部分手机文件预览器不执行 HTML 脚本，请使用浏览器或静态站点，而非系统文件预览。

## 四个页面

- **选购**：按蔬果（含鸡蛋）、肉类、干货、调味、冲饮零食、日用挑东西。支持默认分类、名称、最近购买和常备优先排序；排序控件位于分类栏下方，采用小号无边框文字按钮，点击后向右展开选项浮层，选好自动收回，也可点外部或按 Escape 取消。支持搜索与手动添加新物品，新物品会留在选购目录供以后使用。
- **菜谱**：内置 6 道家常菜、5 锅汤；一键加入菜单、合并食材，按人数换算参考份量。排骨／煲汤骨共用身份；五花肉可切换酸梅酱版与八角版；没有山药汤。做法注明用户配方与补充参考的区别。
- **清单**：按超市区域分组，勾选已买并划线；支持隐藏已买、分享文字清单、重置本次选购。勾选才写入购买记录；取消勾选可撤回关联的当次记录。
- **小厨房**：常备余量滑块（调料、油、米、燕麦、Milo、蛋白粉等）、生鲜库存，以及最近 30 天的购买记录。常备品和生鲜都能单独添加；录入库存不会伪造购买记录或加入清单。

## 清单、库存、历史各自保存

| 操作 | 本次清单 | 库存与余量 | 购买记录 |
|---|---|---|---|
| 开始新的一趟 | 清空选菜、补货和勾选 | 保留 | 保留 |
| 每日自动重置（默认关闭） | 跨日后打开、返回或切页时清空 | 保留 | 保留 |
| 勾选已买 | 划线完成 | 记为还有；慢消耗品新的一份设为 100% | 新增一笔 |
| 滑动余量 | 影响是否略过调料 | 仅按手动调整保存 | 不伪造采购记录 |
| 选菜 | 合并同名食材和参考用量 | 不自动扣减 | 不新增 |

生抽、蚝油、料酒、油等慢消耗品的余量不会随着清单重置。正库存调料在选菜时略过；主动补货时仍可确认再买。生鲜在七天内买过，或仍标为家里有，再次加入时会提醒：勾选确实要买的，其余本次略过。已经在当前清单的东西不重复加行。

滑块是剩余量的手动估计，不是按克数计算的自动消耗模型。买新的一份会重置为 100%，不是多瓶库存台账。未记录的库存会显示「未记录／待确认」，不会假设实际拥有数量。

日期按 `Asia/Kuala_Lumpur` 计算。每日自动重置在「备份与导入／重置与备份」里开启，后台不会运行定时清理。过去 30 天是展示范围，完整历史仍保存在数据中。记录支持新旧排序、单笔删除和撤销；关联本次误勾的记录可撤回勾选及该次库存变化，后续手动改过的库存保留。生鲜使用「用完了／还有／很多」三档滑条，只停在三个位置，也可直接点文字；当前档位使用柔和砖红／叶绿／深绿并加粗。旧的「还有」保持中档，未知库存保留「待确认」。三档随家庭同步、备份与重置保留，不记录虚构的采购。常备滑块在 0–100% 连续变色，卡片仅保留一个大号余量；未知余量保持中性。

## 数据与后续加菜

本机模式保存在当前浏览器的 `localStorage`（键 `little-basket:v1`）。家庭模式使用专属链接，自动连接并共享清单、库存、余量、菜谱和完整购买历史；不需要家人注册、邮箱或密码。不同家庭的缓存隔离。

首次部署、数据库初始化、家庭链接与 Free 配额见 [Supabase 设置说明](supabase/README.md)。公开 Project URL 与 Publishable key 在 `site-config.json`，不含家庭访问凭证。**这些配置就位不等于家庭同步已完成验收；正式站点已部署；有效家庭链接的真实双设备读写仍由家庭设备验收。**

应用打开后断网可先保存，恢复网络会补传。家人同时修改时先确认保留哪份，不静默覆盖；JSON 备份继续用于恢复误操作和迁移，不包含家庭连接码。导入会先验证并确认替换，已连接时也会同步给家人。换设备前确认「已同步」，或先导出备份。

后续新菜优先通过对话整理，维护 HTML 中的 `SEED_RECIPES` 和 `SEED_INGREDIENTS`。内置数据以稳定 ID 合并，更新文件会补入新菜，不会清空已有购买记录和库存。用户在 App 内修改过的做法会保留。App 里也能添加和编辑菜谱，「在学的」页有相同入口；新菜默认标为在学。新增菜先使用通用插画，专属图片可通过对话整理后更新进仓库。来源链接支持多条：填好一行后自动出现空白行，空行不保存；已有的单条来源会兼容显示。

读不到旧存储时，不覆盖原记录；浏览器拒绝保存或存储空间不足时，会显示未保存提示并允许导出备份。

当前环境已具备 Python Playwright 与 Chromium：

```bash

python3 tests/test_cloud_sync.py

python3 scripts/verify_design_capabilities.py

```

浏览器测试覆盖 320–1440 px、库存与清单独立重置、历史、提醒、滑块、菜谱合并、配方切换、备份恢复、旧数据迁移、保存保护及无外部资源依赖。测试输出写在忽略的 `.test-results/` 中。应用本身不依赖这些测试工具。同步测试使用 RPC 替身，线上 HTTPS 已返回 200，内容与当前构建逐字节一致；真实无效链接 RPC 拒绝已验证。有效家庭链接的真实双设备同步、实际 iPhone／Safari 尚未验收。此环境 Chromium 直连线上站点因代理 CA 信任报错，未绕过 TLS 校验；手机尺寸交互在本机服务完成验证。
