# 手机界面走查 · 2026-10-20

本轮在同一实现中分两次采用家庭用户与 UI/UX 专家视角检查。使用隔离的浏览器测试数据；未操作真实家庭记录；走查阶段未提交、推送或部署到 GitHub。沿用已确认的 taste / frontend-design 方向，保留名称、字体和配色。

## 已完成的需求

- 选购双列插画由手机上的 42 px 调整为 64 px，三列调整为 52 px，单列保持 44 px。双列名称为 15 px、600 字重，辅助状态保持次级；调整名称区高度，使放大插画不会增加无意义的卡片留白。使用原有 192 px 透明 WebP，不放大到源图以上，也不增加下载量。
- 名称缩短为「酸梅酱」「炼奶」「Milo」。已保存的旧名称兼容迁移，保留旧称作为搜索别名，不更换食材 ID、不清库存、不重建购买记录，也不覆盖其他自定义名称。
- 常备余量与生鲜库存各有独立搜索；匹配名称及别名，显示结果数，一键清空。分区搜索词与页签在当前窗口刷新后保留，不写进家庭同步数据。购买记录页不显示库存搜索框。
- 切页后的主内容仍接收焦点，保留辅助技术定位，但不再绘制整页默认焦点框。键盘操作的按钮、滑条、输入框及备注展开项仍保留可见焦点。

## 第一轮：家庭用户视角

走查路线：找常备品 → 用别名搜索 → 调整余量 → 刷新 → 切换生鲜搜索 → 添加新常备品 → 选菜 → 写单项备注 → 移除并撤销 → 去完整清单。

| 发现 | 影响 | 处理结果 |
|---|---|---|
| 搜索后添加不同名称的物品，旧筛选会隐藏新物品 | 用户容易以为保存失败，再次添加 | 必要时清空目标分区筛选，滚动到刚保存的物品；另一个分区的搜索词保留 |
| 添加常备品后改成「干货」分类，会自动取消慢消耗 | 米、麦片可能被放进生鲜库存 | 从库存入口添加时，分类变化不覆盖慢消耗选择；在常备分区添加干货仍留在常备余量 |
| 搜不到时原本没有反馈 | 用户无法区分没有库存与搜索没匹配 | 给出结果数、空状态和清空入口，并说明仅搜索本分区已加入的物品 |
| 改名可能让旧别名搜不到，或失去历史关联 | 用户难以找回原有物品 | 保留别名、稳定 ID、余量和购买历史；兼容「美禄」「苏州梅酱」「罐头炼奶」 |

实际验证：搜索「美禄」得到 Milo；搜索「青葱」得到葱。搜索「审阅用」并将麦片余量设成 100%，刷新后仍保留搜索和余量，没有产生采购记录。新增麦片在当前筛选不匹配时能直接看见。备注在预览、撤销及完整清单中一致。

## 第二轮：UI/UX 专家视角

检查范围：信息层级、触控区域、焦点、对齐、窄屏、文字换行、展开后的输入宽度、浮层主次。

| 发现 | 影响 | 处理结果 |
|---|---|---|
| 插画小于其在卡片中的识别任务 | 需要依赖文字逐张阅读 | 双列 64 px、三列 52 px；名称、状态和加入按钮分别承担识别、说明、操作 |
| 切页会把焦点移到整个主内容，触发浏览器默认框 | 大范围蓝框像误选或异常状态 | 仅取消主容器框，保留实际控件的键盘焦点与 Tab 顺序 |
| 320 px 下「加新东西」按钮文字会折行 | 工具按钮显得拥挤、层级不稳 | 标题区操作按钮保持单行，不压缩按钮自身 |
| 清单预览标题、数量和列表分界拥挤，备注及撤销同层 | 阅读顺序不清楚，次要操作抢注意力 | 浅绿头部统一标题和数量；白底食材；赭色撤销；绿色完整清单主操作；说明放在主按钮下 |
| 备注输入放在狭窄文本列会难以编辑 | 小屏一行只能写少量字 | 展开后占满列表可用宽度，320 px 屏下输入宽度超过 230 px，16 px 输入字号 |

实测 320 / 390 / 430 / 768 / 1440 px 的一、二、三列，共 15 个组合：加入按钮至少 44 px 高，图文不相交，页面不横向溢出。手机备注展开时，完整清单按钮仍在浮层内可见；撤销后单项备注保留。另以触摸模拟检查页签、焦点及刷新。

## 后续优化与验收边界

- **家庭链接入口已继续优化。** 已连接后顶部始终显示「家庭厨房」与同步状态，打开后可直接看见「家庭专属链接 → 复制家庭链接」。复制成功、自动复制受限、系统分享取消都有面板内反馈。失效或断开时清掉备用链接显示；没有把专属链接写进家庭数据或公开配置。
- **悬浮篮已支持浏览时收窄。** 手机向下滚动时变为 44 px 小图标并保留数量；向上滚动、回到顶部、滑到底部或键盘聚焦时恢复，缩小时仍可一键打开。停下阅读时保持小尺寸，避免反复弹出。它仍占用右下方一小块区域；末尾留白已验证可让最后一项完整滚到按钮上方。
- 浏览器检查使用 Chromium 与触摸模拟，未把它描述为真实 iPhone / Safari 验收。真实家庭连接的双设备验证仍需家庭设备；同步回归使用 RPC 替身。
